# D-0020 标签页默认在后台打开

- 状态：有效
- 日期：2026-11-14
- 决策者：作者
- 服务于：
  - 作者预期：[overview.md「不打扰作者」](../overview.md)
  - 上游决策：[D-0019](0019-background-tab-new-group.md)

## 背景

`browser.create_tab`、`browser.open_tab` 的 `active` 和 `browser.switch_tab` 的 `activate` 原来默认是 true：Agent 不特意说明，标签页就会切到前台，Braiser 还会把 Chrome 窗口提到最前面。作者认为这没什么用，倾向于干脆删掉。agent 说明了切到前台仍有用的两种情况（页面在后台不能正常工作；需要作者亲手登录或验证），给出"删掉参数"和"保留参数、默认 false"两种做法，作者选了后者（2026-11-14）。

## 决策

- 三个参数默认都是 false：只移动 Braiser 的工作焦点，不切换 Chrome 前台，也不提起窗口。`open_tab` 不传时保持标签页原来是否在前台。
- 工具说明写明只在两种情况下传 true：页面在后台不正常（只在可见时加载的内容、停住的计时器），或需要作者亲手操作（登录、两步验证、人机验证）；并说明 true 会把 Chrome 窗口提到最前。
- 人在终端里运行的 `npm run switch-tab` 仍然切到前台，因为是作者自己发起的。

## 考虑过、没有采用

- 删掉参数、永远在后台：更简单，但页面在后台不正常时 Agent 自己往往发现不了，也无法自行处理，只能请作者去点。

## 代价

Agent 默认看到的是后台标签页，个别依赖"可见"才加载内容的页面可能不完整，要靠 Agent 判断后再传 true。

## 什么时候应该重新考虑

Agent 经常因为页面在后台不完整而出错，或者 Agent 滥用 true 打扰作者时。
