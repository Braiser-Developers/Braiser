# D-0002 采用 SSH 反向隧道并区分本机与远程模式

- 状态：有效
- 日期：2026-11-12
- 决策者：讨论
- 服务于：[作者预期](../overview.md)、[D-0001](0001-existing-browser-architecture.md)

## 背景

作者希望服务器上的 Agent 操作本机浏览器。作者对 SSH 反向隧道说“我觉得这个方案可以”，并对统一启动入口及首版范围说“可以”（2026-11-12）。

作者提供的当前目标环境：本机可以通过 SSH 连接一台远程 Linux 服务器（具体登录名和地址按作者要求不写进仓库）。目标地址由命令参数提供，不是工具固定配置。

## 决策

Linux 运行 MCP，浏览器主机运行 daemon 和扩展。本机发起 SSH，把服务器 127.0.0.1:27833 转到本机 127.0.0.1:17833。连接地址、模式和请求超时可配置；首版地址仅接受 IPv4 回环 ws。远程模式永不自动启动 daemon；本机模式仅在连接被拒绝时自动启动，认证或协议错误必须报告。MCP 与 CLI 共享生命周期逻辑。

## 考虑过、没有采用

VPN、直连公网 WSS、HTTP MCP 和中继服务：当前固定两台机器已有 SSH，暂不增加组网或服务部署。

## 代价

本机必须在线，SSH 服务端需要允许转发；首版不做跨机器文件传输、多 Agent 隔离或常驻部署。

## 什么时候应该重新考虑

多设备、多使用者或无法使用 SSH 时。
