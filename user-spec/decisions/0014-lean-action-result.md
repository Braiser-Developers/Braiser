# D-0014 动作后只返回成败和大的变化

- 状态：有效（未实现）
- 日期：2026-11-13
- 决策者：讨论
- 服务于：
  - 作者预期：[overview.md「observe 改版」](../overview.md)

## 背景

现有 `browser.act` 只返回是否执行和"请重新 observe"，Agent 每做一步都要整页重看，这是最费 token 的地方。全面比较前后页面很难：Playwright 做过增量快照，后来认为效率不高，删掉了。轻量的做法有先例：browser-use 把新出现的可交互元素标成 `*[编号]`；Playwright 有按"角色 + 名称"比较两份快照找新节点的函数（见 [browser-use 资料](../../references/browser-use.md)、[Playwright MCP 资料](../../references/Playwright-MCP.md)）。agent 建议只做容易和中等的两档，作者同意，并补充：动作结果需要的信息很少，只返回可交互元素的变化即可，不需要文字。

## 决策

`browser.act` 返回：

1. 动作是否执行成功；
2. 容易判断的大变化：网址或标题是否改变、是否打开了新标签页、是否开始了下载；
3. 可交互元素的变化：动作前后各取一份"角色 + 名称"清单，列出新出现和消失的元素（数量过多时截断并给出总数）。

不返回文字内容，不做整棵树的结构对比。需要细节时 Agent 自己再调用 observe。

## 考虑过、没有采用

- 动作后自动返回整页快照（Playwright MCP 早期默认）：最费 token。
- 返回新出现的提示和报错文字：作者认为文字不重要，只需要看出大变化。
- 全面的前后差异：单页应用经常整块重绘，难以对齐，Playwright 已放弃类似做法。

## 代价

- 报错只能从"出现了新元素"间接看出，具体内容要再 observe。
- 浏览器原生对话框（alert、confirm）会阻塞页面，首版无法报告。

## 什么时候应该重新考虑

Agent 经常因为信息不够而多调一次 observe，或者变化清单经常误报、漏报时。
